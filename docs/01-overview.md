# 01 · 项目概述与需求分析

> 状态：设计定稿 · 2026-08-27

## 1. 项目背景

站长拥有域名 **netupdown.com**（net + up/down，寓意"上传与下载"），希望搭建一个长期运营的自研产品站，解决三件事：

1. **集中展示自研产品**：通过统一的品牌门面呈现产品定位、平台能力与开发进展。
2. **可靠发布软件版本**：提供官方下载页、版本历史、更新日志与多平台安装包。
3. **服务应用在线更新**：让自研客户端可以直接检查新版本并获取匹配的安装包。

市面上现成方案都不完全匹配：博客程序（WordPress/Halo）缺少版本与文件分发模型；网盘程序（AList/Cloudreve）缺少"应用"的内容形态与 SEO；GitHub Releases 无法自定义门面、国内访问差。因此自研一个专用程序，用 Go 实现单二进制、低资源、易部署。

## 2. 产品定位

**NetUpDown —— 独立开发者的软件发布与更新中心。**

- 一句话：像一座只展示自己产品的 App Store 门户。
- 内容形态参考：GitHub Releases（版本模型）、果核剥壳/423Down（下载站形态）、F-Droid（更新元数据）、AList（存储驱动思想）、Halo（主题机制）。
- 关键差异点：
  - 公开站点只展示「**自研**」产品；历史收录类型仅为数据兼容保留，不进入公开目录；
  - 每个文件支持**多下载源**（托管存储 + 网盘外链），访客自选；
  - 自带**更新检查 API**，自研应用可直接把本站当更新服务器；
  - 前台**主题可插拔**、**亮/暗切换**，视觉是产品力的一部分。

## 3. 角色与使用场景

| 角色 | 说明 | 典型场景 |
|---|---|---|
| 管理员（站长） | 唯一必须角色 | 发布应用与版本、上传文件、配置存储与主题、看统计 |
| 访客 | 匿名浏览者 | 逛首页/分类、搜索、看详情、选下载源下载、订阅 RSS |
| 应用客户端 | 站长自研应用的程序 | 启动时调用 check-update API，提示/强制用户升级 |
| 注册用户（P2） | 可选开放 | 评论、收藏（默认关闭注册） |

### 核心用户故事

- 作为站长，我发布自研应用 v1.4.1：填更新日志 → 上传 Windows/macOS/Linux 各架构安装包 → 系统自动算出大小与 SHA256 → 为每个文件再补一个蓝奏云外链 → 点击发布；老版本自动归入历史版本。
- 作为站长，我同时维护多款自研产品：访客可以按产品系列和平台浏览，并清楚看到每款产品的最新进展。
- 作为访客，我在详情页看到"Windows x64 安装版 / 便携版"两个文件，各有"直链下载（推荐）"与"蓝奏云（提取码 abcd）"两个源，直链支持断点续传。
- 作为自研应用，我启动时请求 `GET /api/v1/apps/myapp/check-update?version=1.2.0&os=windows&arch=amd64`，得到最新版本、更新日志与下载地址；若当前版本低于站长设置的最低版本，收到"强制更新"标记。
- 作为站长，我把主题从 Aurora 换成新装的社区主题，前台立即生效；再把主色从蓝色改成绿色（主题配置项），无需改代码。

## 5. 非功能需求

| 类别 | 要求 |
|---|---|
| 性能 | 命中缓存的 SSR 页面 TTFB < 100ms；1C1G VPS 支撑 100 并发浏览；下载走 302 或流式转发，内存占用与文件大小无关 |
| 部署 | 单二进制 + SQLite 零外部依赖即可运行；`data/` 目录整体搬迁即完成迁移；支持 Linux/Windows/macOS、amd64/arm64 |
| SEO | 前台全部服务端渲染，无 JS 也能完整浏览与下载 |
| 兼容 | 支持近两年主流浏览器（Chrome/Edge/Safari/Firefox），不支持 IE |
| 可维护 | 分层清晰、golangci-lint 零告警、核心逻辑（版本比较/下载决策/存储驱动/上传合并）必须有单元测试 |
| 资源自托管 | 前台不依赖任何境外 CDN（JS/CSS/字体全部本地化），保证国内访问速度 |
| 隐私合规 | 下载日志 IP 支持匿名化选项；若境内主机部署需 ICP 备案（见 10 册） |
| 内容合规 | 收录第三方软件仅提供官方渠道或注明来源转存，站点提供免责声明页；不收录破解/侵权内容 |

## 6. 明确不做（Non-Goals）

- 不做多租户 SaaS，单站点单管理员为主；
- 不做支付、付费下载、License Key 分发（远期另议）；
- 不做应用自动构建/CI（构建产物由站长上传或从 GitHub 同步）;
- 不内置病毒扫描（详情页按 SHA256 生成 VirusTotal 查询链接即可）；
- 不做 P2P/BT 分发。

## 7. 成功标准（v1.0）

1. netupdown.com 上线，站长可完整走通"创建应用 → 发布版本 → 访客下载"闭环；
2. 至少一个自研应用通过 check-update API 实现在线更新；
3. 默认主题在桌面与移动端、亮暗两种模式下均达到"可当作品展示"的完成度；
4. 存储可在本地与 R2 间自由选择；网盘外链带提取码的下载体验完整；
5. 单机部署文档完善，备份脚本可用。
